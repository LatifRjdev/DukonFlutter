# Mobile L10n (AppLocalizations) Conventions

- Source of truth is `app/lib/l10n/app_ru.arb` (Russian, the template locale) — `app_tg.arb`/`app_uz.arb` are translated separately; never hand-edit the generated `app_localizations*.dart` files, they come from `flutter gen-l10n`
- Keys are grouped in contiguous prefix blocks by feature (`dashboard*`, `zReport*`, `inventory*`, `importProducts*`, `a11y*`, `snack*`, etc.) — a key's prefix determines which block it physically lives in
- **If you rename or re-scope a key's prefix, move it to the matching block in the same commit** — a key whose prefix disagrees with its physical location is a bug in the file's organization, not just cosmetic
- Only mint a feature-prefixed key for copy that's genuinely specific to that screen; reuse or add an unprefixed generic key (`save`, `cancel`, `today`, `price`, etc.) for anything that plausibly belongs elsewhere too — the discriminator is the string's *meaning*, never *where it currently renders*
- Before adding any new key, check for an existing one with the same or equivalent value — grep the `.arb` first
- When rendered output is `label + separator + value` (e.g. "Долг: 500"), use one full-sentence placeholder key rather than reusing a bare label key via manual string interpolation — keeps the separator translatable
- **The test for whether to collapse two `Text` widgets into one composite placeholder key is *contiguous text run* vs *distinct layout slots*, not "does it look like label + value":**
  - **Collapse** when the two render as a single contiguous run — adjacent in a start-aligned or wrapping `Row`, sharing a type style, with the separator characters living inside a Dart string literal (e.g. a label literal `'На складе: '` with its trailing space). Leaving these split would force a key whose value carries layout-significant trailing whitespace.
  - **Keep separate** (colon-suffixed label key + its own value `Text`) when *layout* assigns them distinct visual slots — `MainAxisAlignment.spaceBetween`, a `Spacer`, table-row alignment, or a differing type scale. There the colon is terminal punctuation on a standalone label rather than an inline separator, the separator is already translator-controlled inside the label key, and the value's edge alignment / type emphasis is load-bearing. Collapsing forces one style across both, so you must either de-emphasize the value or over-emphasize its label.
  - Precedent: `product_list_page.dart`'s stock line was correctly collapsed (contiguous run); `refund_page.dart`'s total and `zakat_calculator_page.dart`'s three `spaceBetween` rows correctly keep separate label keys (`refundTotalLabel`, `zakatCalculatorTaxableAmountLabel`, etc.).
- Add an `@key` description for any key whose meaning isn't obvious, especially near-duplicates of an existing key (state explicitly how they differ)
- Interpolated placeholders are typed `String` (pre-format the value, then interpolate) — not `int`/`num`, no ICU `plural`/`select`, to keep extraction diffs behavior-preserving. This is a uniform, deliberate convention across the whole file (every existing placeholder is `String`) — don't "fix" one key to `int`/`num` in isolation; a mixed convention is worse than a uniform imperfect one, so any change here has to be a deliberate sweep across all placeholders, not a drive-by in an extraction task
- `l10n.yaml` sets `untranslated-messages-file: l10n_untranslated.json` — run `flutter gen-l10n` and check this file to see the current tg/uz translation backlog; it's a tracked, reviewable artifact, not a build byproduct to ignore
