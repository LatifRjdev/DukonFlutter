# DukonPro full-stack QA — 2026-05-06

End-to-end audit run against a live stack: Postgres + Redis containers,
NestJS API on `:4455`, Next.js admin on `:3001`, Flutter app on
Android emulator-5554 (admin auth, real store, real subscription).

## Verdict

🟡 **Yellow** — no crashes anywhere, but **two P0/P1 blockers** found that
affect actual users.

## Critical findings

### P0 — Admin panel is functionally broken in a real browser
Source: `qa/2026-05-06-admin-audit.md`

The admin panel logs you in (HttpOnly cookie set on `:3001`), but every
list-page client fetch to `:4455/api/admin/*` returns **401 "Invalid
or expired token"**. Reason:
- Backend `JwtAccessStrategy` reads JWT only from
  `Authorization: Bearer …` header.
- Browser `admin/lib/api.ts` calls API with `credentials: 'include'`
  but **no Authorization header**.
- Cookie ≠ Bearer header → strategy rejects.

Effect: dashboard loads but every widget shows "Failed to fetch". User
list, payment approvals, audit logs — all dead.

**Fix path:** proxy admin API calls through Next.js server (read cookie
server-side, attach Bearer header on the way to the API). Same pattern
the login route already uses.

**Bonus issue from same audit:** port `:3000` was occupied by an
unrelated project (`Desktop/magaznov`). The admin starts on `:3001`
when you `npm run dev` from the DukonPro tree, but anything documented
as "admin on :3000" is wrong on this machine.

**Bonus issue 2:** `admin/.env` ships with empty `JWT_ACCESS_SECRET=`
and `API_INTERNAL_URL=`. No startup assertion catches this — the panel
boots and login fails opaquely. Need a fail-fast check.

### P1 — Mobile silently logs user out on token expiry
Source: `qa/2026-05-06-mobile-clickpath.md`

After 65 min of idle, the app dropped to login screen. API log shows
**zero 401s and zero `/api/auth/refresh` calls** in the gap. The app is
either checking `exp` locally and ejecting users without trying to
refresh, OR the refresh interceptor is wired but failing silently.

For a POS app whose value prop is "offline-first, works during a slow
shift", this is a real regression risk before launch.

**Fix path:** audit `app/lib/core/network/api_interceptor.dart` — it
should retry on 401 by hitting `/api/auth/refresh` with the stored
refresh token, and only force-logout if refresh itself fails.

## Module-by-module status

### Backend API — NestJS @ `:4455`
Source: `qa/2026-05-06-api-audit.md`

- **130 / 124 routes PASS** (one route called twice for cross-store leak test)
- **0 hard FAIL**
- 2 SHAPE_ISSUE (silent-reset risks):
  - `PUT /api/stores/:storeId/receipt-template` accepts `{}` and
    persists empty template
  - `POST /api/stores/:storeId/zakat/settings` accepts `{}` and creates
    defaults (upsert behavior)
- 3 AUTH_ISSUE (advisory):
  - `/api/currencies/rates`, `/rates/history`, `/rates/fetch`
    reachable without JWT. Likely intentional (public exchange rates
    from NBT) but inconsistent with the rest of the API. Confirm or
    attach JwtAuthGuard.
  - Auth validation messages mix RU + EN in the same response.
- **No cross-store data leak** — every `/api/stores/:storeId/*`
  correctly 404s on a foreign storeId.

### Admin panel — Next.js @ `:3001`
Source: `qa/2026-05-06-admin-audit.md`

- 11 page routes discovered, all return 200 / SSR-render OK
- Middleware correctly redirects unauthenticated requests
- Destructive handlers (`/api/admin/users/:id/block`, etc.) all wired
  in source; not exercised in the audit
- **All client-side data fetches will 401 in real browser** — see P0
- Next.js 16 deprecation: `middleware.ts` should migrate to `proxy.ts`

### Mobile app — Flutter on Android
Source: `qa/2026-05-06-mobile-clickpath.md`

- All 5 bottom-nav tabs render, **0 crashes**, no ANRs
- Login + create-store + dashboard flow works end-to-end
- Ещё drawer exposes 9+ submodules (История продаж, Сотрудники, Смены,
  Зарплата, Роли и права, Клиенты, …)
- Bottom-nav Касса button is visually permanent (FAB-style), doesn't
  reflect tab state — UX confusion, P2
- Silent logout after token expiry — see P1
