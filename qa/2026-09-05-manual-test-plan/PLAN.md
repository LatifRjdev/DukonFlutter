# План ручного функционального теста мобильного приложения Dukon

Дата составления: 2026-09-05.

## Как пользоваться этим планом

- План идёт **сквозным сценарием**: от установки приложения и регистрации до
  полного набора CRUD-операций по каждому модулю — в том порядке, в котором
  реальный владелец магазина проходил бы путь первого запуска.
- Каждый пункт — чекбокс `[ ]`. Отмечайте `[x]` по мере прохождения.
  Формат пункта: **Шаги → Ожидаемый результат**.
- Там, где для сущности предусмотрены Create/Read/Update/Delete — это явно
  разбито на подпункты **C/R/U/D**, даже если по факту какая-то операция в
  приложении отсутствует (в этом случае — задача теста подтвердить её
  отсутствие явно, не пропустить молча).
- Понадобится минимум **2 тестовых устройства или 2 профиля ролей**
  (Владелец + Кассир/Админ/Складовщик) для проверки прав доступа — см.
  раздел 21.
- Раздел 24 — **регрессионный чек-лист** по всем 48 багам, найденным и
  исправленным в ходе предыдущих аудитов (см.
  `qa/2026-08-25-mobile-functional-spec/SPEC.md`), плюс 2 известных
  оставшихся ограничения. Дублирует часть пунктов из основного сценария
  намеренно — используйте его как быстрый прогон перед релизом, не
  проходя весь план заново.
- Тестировать в **обеих локалях, где применимо** (ru как основную,
  выборочно tg/uz на предмет отсутствия непереведённых ключей — см.
  `l10n_untranslated.json`), и в **светлой и тёмной теме** хотя бы один раз
  на ключевых экранах.
- Тестировать **в оффлайне** там, где отмечено 📴 — выключить
  сеть/перевести телефон в авиарежим перед шагом.

## 0. Подготовка окружения

- [ ] Приложение установлено на чистое устройство/эмулятор (без старых
      данных — либо через "Выйти из аккаунта" + переустановку).
- [ ] Backend/dev API доступен, версия соответствует тестируемому билду.
- [ ] Подготовлены минимум 2 телефонных номера для регистрации (основной
      владелец + второй пользователь для многопользовательских сценариев).
- [ ] Есть доступ создать/сбросить тестовые данные на бэкенде при
      необходимости (застрять с "грязными" данными — типичная причина
      неверных результатов теста).
- [ ] Bluetooth-принтер (или эмулятор ESC/POS) доступен для раздела 16.
- [ ] Проверена версия приложения/сборки, зафиксирована в отчёте о
      прохождении теста.

## 1. Регистрация, вход, восстановление пароля

### 1.1 Онбординг и первый запуск
- [ ] Splash-экран показывается кратко, без зависаний, ведёт на
      Onboarding (если первый запуск) или Login (если уже был вход).
- [ ] Onboarding: пролистать все слайды свайпом, кнопка "Пропустить" (если
      есть) работает, финальный слайд ведёт на Login/Register.

### 1.2 Регистрация (Create аккаунт)
- [ ] Открыть "Регистрация" с экрана входа.
- [ ] Отправить форму с пустыми полями → инлайн-ошибки по каждому
      обязательному полю, запрос не уходит.
- [ ] Ввести телефон без кода `+992` → ошибка формата (если есть
      валидация кода страны).
- [ ] Ввести пароль короче 6 символов → ошибка "минимум 6 символов".
- [ ] Пароли не совпадают в полях пароль/подтверждение → ошибка.
- [ ] Успешная регистрация с валидными данными → переход дальше по потоку
      (OTP либо сразу в приложение — зафиксировать реальное поведение).
- [ ] Повторная регистрация с уже использованным номером телефона → внятная
      ошибка (409/"уже существует"), не сырой текст исключения.

### 1.3 Вход (Login)
- [ ] Вход с неверным паролем → ошибка, без утечки, существует ли аккаунт.
- [ ] Вход с несуществующим номером → ошибка.
- [ ] Вход с валидными данными → попадание на `/home`.
- [ ] Поле пароля скрыто по умолчанию, есть переключатель показать/скрыть
      (если предусмотрен).

### 1.4 Забыли пароль → OTP → новый пароль (сквозной поток)
- [ ] "Забыли пароль" → ввести телефон → код отправлен (реальная SMS/канал
      доставки, если тестовое окружение это поддерживает).
- [ ] Экран OTP: ввод 6 цифр автосабмитится без нажатия кнопки.
- [ ] Неверный код → ошибка сервера показана снекбаром, поле не сбрасывает
      прогресс молча.
- [ ] Таймер повторной отправки: кнопка "Отправить код повторно" появляется
      только через 60 сек, до этого недоступна.
- [ ] Верный код при потоке "Забыли пароль" → переход на "Создать пароль"
      (**не** прямой вход в старый аккаунт — регресс находки №3).
- [ ] Экран "Создать пароль": пароль короче 6 символов → ошибка;
      пароли не совпадают → ошибка.
- [ ] Успешная смена пароля → подтверждение, возможность войти новым
      паролем.
- [ ] Старый пароль после смены больше не работает.

### 1.5 Выход из аккаунта
- [ ] "Выйти из аккаунта" → диалог подтверждения → отмена не выходит.
- [ ] Подтверждение выхода → сброс store/auth состояния → редирект на
      `/login`; повторный запуск приложения не восстанавливает сессию.

## 2. Создание и управление магазином

### 2.1 Create — создание магазина
- [ ] После первого входа без магазинов → принудительный переход на
      "Создать магазин".
- [ ] Отправка пустой формы → ошибки по обязательным полям.
- [ ] Успешное создание → магазин появляется как активный, доступен на
      Dashboard.

### 2.2 Read/Update — "Мои магазины"
- [ ] Список магазинов показывает все магазины пользователя.
- [ ] Тап по магазину → переключение активного магазина, весь контент
      (товары, продажи, касса) перезагружается под выбранный магазин.
- [ ] Открыть форму редактирования существующего магазина → поля
      предзаполнены реальными данными.
- [ ] Отправить форму редактирования с пустым обязательным полем →
      **зафиксировать факт**: валидации нет (известное ограничение) —
      можно ли сохранить магазин без названия?
- [ ] Сохранить изменения → магазин обновился, изменения видны в списке.

### 2.3 Multi-store
- [ ] Создать второй магазин.
- [ ] Переключение между магазинами не путает данные (товары/продажи
      одного магазина не показываются в другом).
- [ ] Название текущего магазина в шапке Dashboard совпадает с активным.

### 2.4 Delete — удаление магазина
- [ ] **Зафиксировать**: есть ли в UI возможность удалить магазин вообще.
      Если нет — не пропускать молча, отметить как подтверждённое
      отсутствие функции.

## 3. Профиль пользователя и безопасность

### 3.1 Read/Update — редактирование профиля
- [ ] Открыть "Профиль" из "Настройки" → поля Имя/Фамилия/Email/Телефон
      предзаполнены реальными данными пользователя.
- [ ] Телефон заблокирован для редактирования (read-only) — подтвердить.
- [ ] Бейдж роли показывает **реальную** роль пользователя (не всегда
      "Владелец" — регресс находок №13/№5).
- [ ] Изменить имя/фамилию/email → сохранить → изменения отражаются в
      шапке настроек и в других местах, где показывается имя пользователя
      (например, чек).
- [ ] "Изменить фото" — зафиксировать: работает ли реально (известно как
      декоративная кнопка-заглушка).

### 3.2 Update — смена пароля
- [ ] Текущий пароль неверный → ошибка, смена не проходит.
- [ ] Новый пароль короче 6 символов → ошибка.
- [ ] Новый и подтверждение не совпадают → ошибка.
- [ ] Успешная смена → выйти и войти новым паролем — работает; старый
      пароль — не работает.

## 4. Товары и склад

### 4.1 Категории — полный CRUD
- [ ] **Create**: добавить категорию с валидным названием → появляется в
      списке и в фильтре товаров.
- [ ] **Create**: пустое название → диалог не закрывается либо явная
      ошибка (зафиксировать реальное поведение — известно: без текста
      ошибки).
- [ ] **Read**: список категорий отображает все созданные.
- [ ] **Update**: переименовать категорию → изменения видны везде, где
      категория используется (карточки товаров, фильтры).
- [ ] **Delete**: удалить категорию, к которой привязаны товары →
      зафиксировать поведение (запрет/предупреждение/тихое отвязывание).
- [ ] **Delete**: удалить пустую категорию → успешно, исчезает из списка.

### 4.2 Товары — полный CRUD (3-шаговая форма)
- [ ] **Create шаг 1**: обязательные поля (название, категория и т.п.) —
      попытка перейти дальше без них блокируется.
- [ ] **Create шаг 2**: цены/остаток — отрицательные значения не
      принимаются; себестоимость > цены продажи — зафиксировать
      (предупреждение или нет).
- [ ] **Create шаг 3**: фото товара — добавить, сохранить.
- [ ] **Create**: успешное сохранение → товар появляется в общем списке
      и в поиске на кассе.
- [ ] **Read**: открыть карточку товара → все поля корректно отображены.
- [ ] **Update**: иконка редактирования на карточке товара → форма
      открывается **в режиме редактирования** (заголовок "Редактировать
      товар", а не "Новый товар") с предзаполненными полями — регресс
      критичной находки №1.
- [ ] **Update**: сохранить изменения → **обновляется существующий товар**,
      **не создаётся дубликат** (проверить через список — количество
      товаров не увеличилось) — регресс находки №1.
- [ ] **Delete**: меню "⋮" → "Удалить" → диалог подтверждения → отмена не
      удаляет.
- [ ] **Delete**: подтверждение удаления → товар исчезает из списка.
- [ ] Пустой список товаров (после удаления всех/на новом магазине) →
      показывает `AppEmptyState` с кнопкой "Добавить товар", не пустой
      экран/краш (страница `EmptyProductsPage` удалена как мёртвый код —
      подтвердить, что инлайн-empty-state работает корректно).

### 4.3 Приход товара (Stock Intake)
- [ ] С карточки товара → "Приход" → экран открывается **с
      предзаполненным товаром и себестоимостью** (регресс находки №24).
- [ ] Указать количество и себестоимость → подтвердить приход → остаток
      товара увеличился на складе (проверить в карточке товара).
- [ ] Приход с нулевым/отрицательным количеством → блокируется валидацией.
- [ ] Приход без выбора поставщика (если поле есть) — зафиксировать,
      обязательно ли поле.

### 4.4 Импорт товаров из Excel
- [ ] "Скачать шаблон" → файл скачивается, открывается, соответствует
      ожидаемому формату колонок.
- [ ] Загрузить корректный файл → превью таблицы показывает строки без
      ошибок → "Импортировать N" → товары появляются в общем списке.
- [ ] Загрузить файл с ошибками в части строк → превью подсвечивает
      проблемные строки построчно.
- [ ] Загрузить файл с ошибкой формата (не xlsx/csv/xls) → явная ошибка
      с сообщением и кнопкой "Повторить", **не просто снекбар** (регресс
      находки №27).
- [ ] Импорт с невыбранным файлом → кнопка "Импортировать" недоступна.

### 4.5 Инвентаризация (Inventory Count)
- [ ] Открыть инвентаризацию с Dashboard ("Инвентаризация" плитка/пункт).
- [ ] Ввести фактическое количество, отличное от системного → сохранить →
      остаток товара скорректирован.
- [ ] Инвентаризация без изменений (фактическое = системному) → сохранение
      не создаёт лишних операций/движений склада (если это проверяемо).

## 5. Касса и продажи (POS)

### 5.1 Корзина — CRUD позиций
- [ ] **Create**: добавить товар через поиск → товар в корзине с
      количеством 1.
- [ ] **Create**: тап по тому же товару повторно → количество
      увеличивается, не создаётся вторая строка.
- [ ] **Create**: добавить товар через сканер штрихкода → код подставляется
      в поиск, товар находится и добавляется.
- [ ] **Update**: степпер `+` — увеличивает количество; **клампится
      остатком на складе** — превысить фактический остаток нельзя
      (регресс находки №6).
- [ ] **Update**: степпер `−` при количестве 1 → удаляет позицию из
      корзины.
- [ ] **Update**: применить скидку (сумма и %) на корзину → итог
      пересчитывается; скидка больше суммы товаров **не уводит итог в
      отрицательное значение** — клампится к 0 (регресс находки №7).
- [ ] **Delete**: кнопка удаления позиции → позиция исчезает, итог
      пересчитан.
- [ ] Пустая корзина → `AppEmptyState` "Корзина пуста", блок оплаты
      полностью скрыт.
- [ ] Выбор клиента для продажи → баллы лояльности клиента подгружаются;
      "Без клиента" сбрасывает клиента и обнуляет списание баллов.
- [ ] Списание баллов лояльности — слайдер клампится максимумом,
      доступным клиенту.

### 5.2 Оформление продажи — все способы оплаты
- [ ] **Наличные**: чипы быстрых сумм подставляют значение; сдача
      считается верно; "Завершить" недоступна пока получено < итого.
- [ ] **Наличные**: "Без сдачи" → получено = итого автоматически.
- [ ] **Карта**: показывает диалог подтверждения суммы (Отмена/
      Подтвердить) перед обработкой — **не мгновенная обработка без
      возможности отмены** (регресс находки №8). "Отмена" не создаёт
      продажу.
- [ ] **Карта**: "Подтвердить" → продажа создаётся, переход на экран
      успеха.
- [ ] **В долг**: выбор клиента обязателен — без клиента кнопка
      "Оформить в долг" недоступна.
- [ ] **В долг**: создать нового клиента прямо из диалога → клиент
      появляется и в общем списке клиентов после.
- [ ] **В долг**: срок оплаты по умолчанию +30 дней, диапазон date picker
      [сегодня; +365 дней].
- [ ] **Смешанная оплата**: проходит через тот же экран, что наличные —
      проверить итоговый расчёт корректен.
- [ ] После любой успешной продажи → **корзина автоматически очищена**
      уже на экране "Продажа оформлена" (регресс находки №2) — вернуться
      на кассу и убедиться, что корзина пуста.

### 5.3 Экран "Продажа оформлена"
- [ ] Сумма и сдача (если > 0) показаны верно.
- [ ] "Печатать чек" — печать (см. раздел 16 про принтер) либо явная
      ошибка "Принтер не подключён".
- [ ] "Отправить в Telegram" → нижний лист: Telegram/WhatsApp/SMS — каждый
      канал реально открывает соответствующее приложение/API.
- [ ] "Новая продажа" → `/home` на вкладке Дашборд.

### 5.4 История продаж — Read + фильтры
- [ ] Список продаж показывает статистику "{N} продаж | {сумма}" и карточки.
- [ ] Фильтр по периоду (Сегодня/Неделя/Месяц) **реально меняет диапазон
      дат запроса** (регресс находки №9) — сравнить количество продаж до/
      после смены чипа.
- [ ] Произвольный диапазон дат через календарь → **реально применяется**
      к запросу (регресс находки №9).
- [ ] Фильтр по способу оплаты — применяется.
- [ ] Фильтр по статусу (Все/Выполнен/Возврат/Отменён) — **реально
      применяется к запросу** (регресс находки №10).
- [ ] Тап по карточке продажи → открывает верную транзакцию.
- [ ] **Известное неисправленное ограничение**: иконка/цвет карточки
      возврата в списке может не совпадать (использует строку `REFUNDED`
      вместо `RETURNED`) — зафиксировать текущее визуальное поведение,
      не заводить это как новый баг повторно.

### 5.5 Детали транзакции и возврат
- [ ] "Печатать чек" из деталей транзакции — работает.
- [ ] Кнопка "Возврат" **скрыта** для уже полностью возвращённой продажи
      (регресс находки №11) — проверить на продаже, оформленной как
      полный возврат ранее.
- [ ] Кнопка "Возврат" **видна** для частично возвращённой продажи (могут
      остаться невозвращённые позиции).
- [ ] Оформить частичный возврат (выбрать часть позиций) → сумма возврата
      пересчитывается динамически по выбору.
- [ ] Оформить возврат без причины (необязательное поле) → проходит.
- [ ] Оформить возврат с ошибкой на сервере (например, отключить сеть
      📴 перед подтверждением) → **пользователь видит сообщение об
      ошибке** снекбаром, кнопка не крутится бесконечно (регресс
      находки №12).
- [ ] Успешный возврат → снекбар успеха, возврат к предыдущему экрану,
      статус продажи обновлён.

## 6. Клиенты

### 6.1 Create
- [ ] Быстрое создание с кассы (диалог "В долг" → "Создать нового
      клиента") — имя обязательно, телефон нет.
- [ ] Полная форма создания клиента (если есть отдельный экран) —
      валидация телефона по формату `+992`.
- [ ] Создание с ошибкой сети 📴 → сообщение через `mapErrorToUserMessage`,
      **не сырой текст исключения** (регресс находки №21).

### 6.2 Read

## 20. Кросс-функциональные и нефункциональные проверки

- [ ] **Тёмная/светлая тема**: переключить на хабе настроек → пройтись по
      5-10 ключевым экранам (Касса, Товары, Дашборд, Настройки, История
      продаж) — нет нечитаемого текста/пропавших иконок.
- [ ] **Локализация**: переключить на tg и на uz по очереди → пройтись по
      тем же ключевым экранам — нет "сырых" ключей вида `notFound` вместо
      текста.
- [ ] **Офлайн-режим сквозняком** 📴: выключить сеть перед началом продажи
      → корзина продолжает работать локально (если предусмотрено) →
      включить сеть → синхронизация подхватывает отложенные операции без
      дублирования.
- [ ] **Ротация/сворачивание**: свернуть приложение в процессе заполнения
      длинной формы (например, добавление товара шаг 2) → вернуться →
      данные формы не потеряны (если ожидается сохранение состояния).
- [ ] **Глубокие ссылки/пуши**: если поддерживаются push-уведомления —
      тап по пушу открывает соответствующий экран, а не просто домашний.
- [ ] **Производительность списка**: список из 100+ товаров/продаж
      скроллится без явных подвисаний.
- [ ] **Повторные быстрые тапы**: быстро тапнуть кнопку оформления
      продажи/сохранения дважды подряд → **не создаётся дублей** (двух
