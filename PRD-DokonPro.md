## 1. Обзор продукта

### 1.1 Описание

**DukonPro** — мобильное SaaS-приложение для комплексного управления розничным магазином. Приложение позволяет владельцам малого и среднего бизнеса вести учёт товаров, осуществлять продажи, отслеживать финансы и управлять персоналом с единого устройства.

### 1.2 Проблемы, которые решает продукт

| Проблема | Решение DukonPro |
|----------|------------------|
| Ручной учёт товаров в тетрадях | Цифровой каталог с автоматическим учётом остатков |
| Отсутствие контроля над продажами | Real-time статистика и история всех операций |
| Сложность подсчёта прибыли | Автоматические финансовые отчёты |
| Нестабильный интернет в регионах | Полноценный офлайн-режим с синхронизацией |
| Отсутствие удалённого контроля | Telegram-бот для владельца с отчётами и алертами |
| Сложность работы с наличностью | Учёт долгов, рассрочек, смен кассиров |

### 1.3 Ключевые преимущества

1. **Офлайн-first подход** — приложение полноценно работает без интернета
2. **Локализация** — интерфейс на русском, таджикском, узбекском
3. **Мультивалютность** — учёт в TJS, USD, RUB с автоматическим пересчётом
4. **Простота** — интуитивный интерфейс для пользователей без технического опыта
5. **Доступность** — тарифы адаптированы под местный рынок

### 1.4 Позиционирование

```
Для владельцев малого и среднего розничного бизнеса в Таджикистане,
которые хотят автоматизировать учёт и увеличить прибыль,
DukonPro — это мобильное приложение для управления магазином,
которое работает без интернета и стоит доступно.
В отличие от 1С, SAP и других решений,
DukonPro создан специально для местного рынка и не требует обучения.
```

## 3. Целевая аудитория

### 3.1 Основные сегменты

#### Сегмент 1: Продуктовые магазины
- **Размер:** 1-3 сотрудника
- **Товаров:** 100-1,000
- **Чек:** 50-500 TJS
- **Потребности:** учёт остатков, контроль просрочки, долги клиентов
- **Тариф:** Старт / Бизнес

#### Сегмент 2: Магазины одежды/обуви
- **Размер:** 1-5 сотрудников
- **Товаров:** 200-2,000
- **Чек:** 200-2,000 TJS
- **Потребности:** варианты товаров (размеры), сезонность, скидки
- **Тариф:** Бизнес

#### Сегмент 3: Хозтовары и стройматериалы
- **Размер:** 2-10 сотрудников
- **Товаров:** 500-5,000
- **Чек:** 100-10,000 TJS
- **Потребности:** импорт из Excel, калькулятор доставки, оптовые цены
- **Тариф:** Бизнес / Премиум

#### Сегмент 4: Сети магазинов
- **Размер:** 5-50 сотрудников
- **Магазинов:** 2-10
- **Потребности:** централизованный контроль, сравнение точек, API
- **Тариф:** Премиум

#### F-PROD-008: Поиск товара по фотографии
| Параметр | Описание |
|----------|----------|
| Приоритет | P1 (High) |
| Тариф | Бизнес, Премиум |

**User Story:**
> Как продавец, я хочу сфотографировать товар и найти его в каталоге, чтобы не тратить время на ручной поиск среди сотен позиций.

**Описание:**
Функция позволяет найти товар в каталоге магазина по фотографии. Пользователь фотографирует товар (упаковку, этикетку) или выбирает фото из галереи. AI-модель сравнивает изображение с фотографиями товаров в каталоге и возвращает список совпадений с процентом сходства.

**Acceptance Criteria:**
- [ ] Кнопка камеры в строке поиска (список товаров и экран кассы)
- [ ] Fullscreen экран камеры с рамкой-фокусом
- [ ] Возможность включить/выключить вспышку
- [ ] Выбор фото из галереи как альтернатива съёмке
- [ ] Экран анализа с индикатором прогресса
- [ ] Список результатов с процентом совпадения (98%, 72%, 45% и т.д.)
- [ ] Возможность открыть карточку товара или добавить в корзину из результатов
- [ ] Экран "Не найдено" с опциями: повторить фото, добавить как новый товар, поиск вручную
- [ ] Сжатие фото до 300KB перед отправкой на сервер
- [ ] Таймаут запроса: 10 секунд, после чего показать ошибку
- [ ] Работа только при наличии интернета (показать сообщение в офлайн-режиме)
- [ ] Минимальное разрешение камеры: 720p

**Технические детали:**
- Image Recognition API (на сервере): сравнение с image embeddings товаров
- При добавлении/обновлении фото товара — генерация embedding и сохранение в vector store
- Endpoint: `POST /api/products/search-by-image` — multipart/form-data с изображением
- Response: массив `{product_id, similarity_score, product}` отсортированный по score desc
- Порог показа: similarity_score >= 0.3 (30%)
- Максимум результатов: 10

**Ограничения:**
- Требуется интернет-соединение
- Товар должен иметь загруженное фото в каталоге
- Качество распознавания зависит от освещения и чёткости фото

#### F-FIN-006: Калькулятор закята
| Параметр | Описание |
|----------|----------|
| Приоритет | P1 (High) |
| Тариф | Все |

**User Story:**
> Как владелец магазина-мусульманин, я хочу автоматически рассчитывать закят на основе товарных остатков, чтобы точно знать сумму обязательной выплаты.

**Формула расчёта:**

*Активы магазина:*
| Компонент | Источник | Метод |
|-----------|----------|-------|
| Товарные остатки | SUM(quantity × cost_price) | Автоматически из каталога |
| Наличные в кассе | Ввод вручную или баланс кассы | Ручной / Авто |
| Дебиторская задолженность | SUM(непогашенных долгов клиентов) | Автоматически из F-FIN-005 |

*Личное имущество (множественные позиции в каждой категории):*
| Категория | Примеры | Метод |
|-----------|---------|-------|
| Банковские счета | "Амонатбонк — основной", "Эсхата — сберегательный" | Ручной, несколько позиций |
| Золото и серебро | "Золотое кольцо", "Цепочка", "Серебряные монеты" | Ручной, несколько позиций |
| Наличные | "Наличные дома", "В сейфе" | Ручной, несколько позиций |
| Транспорт | "Toyota Camry 2020", "Газель (рабочая)" | Ручной, несколько позиций |
| Недвижимость | Для продажи/инвестиции (НЕ личное жильё) | Ручной, несколько позиций |
| Инвестиции | "Вклад в банке", "Акции" | Ручной, несколько позиций |
| Другое | Пользовательская категория | Ручной |

> **Примечание:** Личное жильё и личный автомобиль (для личного пользования) НЕ облагаются закятом. Пользователь сам определяет, какое имущество является торговым/инвестиционным.

*Вычеты (множественные позиции):*
| Категория | Примеры | Метод |
|-----------|---------|-------|
| Долги поставщикам | Автоматически из модуля поставщиков | Авто, вычитается |
| Личные долги | "Кредит — Амонатбонк", "Долг Ахмаду" | Ручной, несколько позиций |

*Итого:*
| Компонент | Формула | Метод |
|-----------|---------|-------|
| **Облагаемая сумма** | Активы магазина + Личное имущество − Вычеты | Авто |
| **Закят** | Облагаемая сумма × 2.5% | Авто |

**Нисаб (минимальный порог):**
- По золоту: 85г × текущий курс золота в TJS
- По серебру: 595г × текущий курс серебра в TJS
- Пользователь выбирает стандарт

**Acceptance Criteria:**
- [ ] Автоматический подсчёт стоимости товарных остатков (SUM quantity × cost_price)
- [ ] Ручной ввод суммы наличных в кассе или автоподтягивание из баланса кассы

- [ ] Редактирование каждой позиции (название и сумма)
- [ ] Удаление позиции с подтверждением
- [ ] Создание пользовательских категорий
- [ ] Подытог по каждой секции (активы магазина, личное, вычеты)
- [ ] Автоматический подсчёт долгов поставщикам (вычитается)
- [ ] Добавление нескольких личных долгов (название + сумма, вычитаются)

```typescript
      mockPrismaService.product.count.mockResolvedValue(2);

      mockPrismaService.product.findFirst.mockResolvedValue(null);
```

### 8.3 Товары

#### GET /api/stores/:storeId/products
**Query Parameters:**
- `page` (int): страница
- `limit` (int): количество на странице (default: 50)
- `search` (string): поиск по названию/артикулу
- `category` (uuid): фильтр по категории
- `inStock` (boolean): только в наличии
- `lowStock` (boolean): заканчивающиеся
- `sortBy` (string): name, quantity, price, createdAt
- `sortOrder` (string): asc, desc

**Response:**
```json
{

      "quantity": 45,
```

Импорт из Excel

- `file`: Excel файл
- `mapping`: JSON маппинг столбцов
- `onDuplicate`: "update" | "skip" | "create"

Поиск товара по фотографии (AI image recognition)

**Request (multipart/form-data):**

**Response (200):**
```json

      "product": {
        "id": "uuid",
        "name": "Кофе растворимый Nescafe 200г",
        "sku": "COFFEE-001",
        "sellPrice": 180.00,
        "quantity": 45,
        "imageUrl": "https://..."
      }
    },
    {
      "productId": "uuid",
      "similarityScore": 0.72,
      "product": {
        "id": "uuid",
        "name": "Кофе растворимый Jacobs 150г",
        "sku": "COFFEE-003",
        "sellPrice": 210.00,
        "quantity": 12,
        "imageUrl": "https://..."
      }
    }
  ],
  "meta": {
    "total": 2,
    "threshold": 0.3,
    "processingTimeMs": 1200
  }
}
```

**Response (200, не найдено):**
```json
{
  "data": [],
  "meta": {
    "total": 0,
    "threshold": 0.3,
    "processingTimeMs": 800
  }
}
```

**Errors:**
- 400: Неподдерживаемый формат изображения
- 413: Файл слишком большой (> 2MB)
- 503: Сервис распознавания недоступен

## 11. Риски и митигация

### 11.1 Технические риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Сложность офлайн-синхронизации | Высокая | Высокое | Использовать проверенные паттерны, начать с простых сценариев |
| Проблемы с производительностью при большом каталоге | Средняя | Среднее | Виртуализация списков, пагинация, индексы |
| Несовместимость с принтерами чеков | Средняя | Среднее | Поддержка популярных моделей, ESC/POS стандарт |
| Изменения в API магазинов приложений | Низкая | Высокое | Следить за обновлениями, оперативно обновлять |

### 11.2 Бизнес-риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Низкая конверсия trial → paid | Высокая | Высокое | Онбординг, поддержка, value в первые дни |
| Конкуренция с бесплатными решениями | Средняя | Высокое | Фокус на офлайн и локализацию |
| Сложность сбора платежей | Средняя | Высокое | Несколько способов оплаты, напоминания |
| Изменения в законодательстве (фискализация) | Низкая | Высокое | Мониторинг, гибкая архитектура |

### 11.3 Операционные риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Потеря данных пользователей | Низкая | Критическое | Регулярные бэкапы, репликация, тестирование восстановления |
| DDoS атаки | Низкая | Высокое | Cloudflare, rate limiting |
| Отток ключевых разработчиков | Средняя | Высокое | Документация, code review, bus factor > 1 |
